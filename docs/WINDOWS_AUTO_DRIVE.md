# PocketNAS Windows Auto Drive

PocketNAS v3 adds an optional Windows client workflow intended for large files and automatic reconnection.

## User workflow

1. Start PocketNAS on Android.
2. On Windows, open the phone's PocketNAS address in a browser.
3. Click **Windows Drive Setup**.
4. Run the downloaded PowerShell file.
5. Approve UAC once.
6. Setup installs WinFsp + rclone when missing, discovers the phone, and mounts it as `P:` or another free drive letter.
7. A hidden watcher starts on Windows sign-in and automatically rediscovers the same phone by its PocketNAS device ID.

## Why this exists

Windows' built-in WebClient/WebDAV redirector has legacy limits and can stall on multi-GB transfers even when the server itself streams correctly. The v3 Windows Drive path uses rclone as the WebDAV client and WinFsp as the Windows filesystem layer.

## Files created on Windows

```text
%LOCALAPPDATA%\PocketNAS\settings.txt
%LOCALAPPDATA%\PocketNAS\rclone.conf
%LOCALAPPDATA%\PocketNAS\PocketNAS-AutoMount.ps1
%LOCALAPPDATA%\PocketNAS\rclone.log
```

A small launcher is also created in the current user's Startup folder.

## Discovery

The watcher checks `/api/status`. It records the stable `deviceId` generated by the Android install, so DHCP/IP changes do not require editing the Windows configuration.

The script first tests the last known URL, then the ARP cache, then reachable local `/24` networks on TCP 8080.

## Authentication

When PocketNAS authentication is OFF, no credentials are stored in the rclone configuration.

When authentication is ON, setup asks for the permanent password. rclone stores an obscured representation in its config; it is not stored as readable plaintext by the setup script.

## Removing the Windows integration

1. Close the PocketNAS drive/rclone process.
2. Delete the `PocketNAS Auto Mount.cmd` file from the user's Startup folder.
3. Delete `%LOCALAPPDATA%\PocketNAS`.
4. Optionally uninstall rclone and WinFsp if no other software uses them.
